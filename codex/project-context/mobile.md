# DuoGoal Android: контекст приложения

Этот файл описывает текущее состояние Android-клиента и обновляется при каждом изменении структуры, архитектуры или сетевого контракта.

## Техническая основа

- Kotlin, Jetpack Compose; минимальная версия Android — API 24.
- Пакет: `com.example.duogoal_android`.
- Текущая ветка с дизайн-прототипом: `design-pages`.
- Единственная activity — `MainActivity`; она отображает `DuoGoalApp`.

## Текущая структура кода

```text
app/src/main/java/com/example/duogoal_android/
├── MainActivity.kt
└── ui/
    ├── DuoGoalApp.kt          # временный ручной back stack и маршруты экранов
    ├── components/            # общие кнопки, иконки, нижняя навигация
    ├── screens/               # Compose-экраны
    └── theme/                 # цветовая тема и типографика
```

Есть экраны: `Login`, `Feed`, `Chats`, `Chat`, `Profile`, `Notifications`, `CreateGoal`, `PartnerPicker`, `GoalActive`, `GoalWaiting`, `Invitation`.

## Что является макетом, а не реализованной функциональностью

- Экран входа не отправляет запросы и содержит демонстрационные значения.
- Экран регистрации отсутствует.
- Навигация реализована локальным списком экранов в `DuoGoalApp`, а не Navigation Compose.
- Контент ленты, профиля, чатов, целей и уведомлений статичен.
- Нет сетевого слоя, моделей данных, репозиториев, ViewModel и защищённого хранения токенов.

## Правила дальнейшей работы

1. Каждая продуктовая фича выполняется в отдельной ветке Android-репозитория вида `feature/<краткое-название>`.
2. Изменение визуального дизайна согласуется с владельцем до внесения правок.
3. Backend HLT не изменяется без отдельного прямого запроса владельца; Android работает только с его опубликованными контрактами.
4. После изменения API или архитектуры обновляются этот файл и `backend.md`; новые или уточнённые запросы к backend добавляются в `../backend-requirements/README.md`.
