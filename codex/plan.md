# План разработки DuoGoal Android

Статус обновляется после завершения каждой фичи. Каждая продуктовая фича создаётся и реализуется в отдельной Git-ветке.

## Принципы

- Android-клиент не меняет HLT backend без отдельного прямого запроса владельца.
- Визуальные изменения согласуются до реализации; новый экран сохраняет существующий визуальный язык, если не оговорено иначе.
- Сетевой код не располагается в Compose-экранах: `UI → ViewModel → Repository → API/локальное хранилище`.
- Секреты, токены и адреса внутренних сред не коммитятся.
- Перед слиянием: тесты, сборка и обновление контекста/контрактов в `codex/`.
- После проверок удаляются ненужные временные файлы и результаты сборки (`app/build/`, корневой `build/`). Сборочные отчёты сначала изучаются; нужный пользователю APK сохраняется. Глобальные кэши Gradle, Android SDK и пользовательские файлы автоматически не удаляются.
- Для GitHub публикуется рабочая feature-ветка; слияние в `main` выполняется после ревью. В коммит включаются только изменения задачи, без посторонних настроек IDE, локальной конфигурации и сборочных файлов. При недоступной авторизации предоставляются команды для отправки вручную.

## Фича 1: критерии готовности

- Пользователь может зарегистрироваться, после чего приложение автоматически получает токены через вход.
- Пользователь может войти по email и паролю.
- Access и refresh токены хранятся в шифрованном виде с ключом Android Keystore.
- При запуске приложение пытается обновить сохранённую сессию; при неуспехе показывает вход, не открывая приватные экраны.
- UI показывает загрузку и понятные ошибки сервера/сети; пароль не логируется и не отображается открытым по умолчанию.
- Для API используется `https://hlt.com`; адрес задаётся в одном месте сборки.
